บทที่ 2 · Memory Management ออก

ชีท memory_mng(3_1) หน้า 70–81 (12 หน้า) — อาจารย์เปิดในคลิปนาที 6:10–17:00

💡 ภาพรวมของบทนี้ในประโยคเดียว หลายโปรเซสต้องแชร์หน่วยความจำ (RAM) ก้อนเดียวกัน OS ต้องตอบ 3 คำถาม: (1) โปรแกรมอ้าง address แบบไหน แล้วแปลงเป็นตำแหน่งจริงอย่างไร (2) จะวางโปรเซสไว้ตรงไหน (3) พอมีช่องว่างกระจัดกระจาย (hole) จะแก้อย่างไร — คำตอบสุดท้ายของบทนี้คือ paging

2.1 Address binding

🗣 อาจารย์พูดตอนเปิดหน้านี้อาจารย์บอกว่า อันนี้จะไม่เน้น แล้วไปพูดเรื่อง dynamic linking กับ static linking

โปรแกรมเขียนด้วยชื่อ (symbolic address เช่น ตัวแปร A, B) แต่ตอนรันต้องใช้ physical address การแปลงนี้เรียกว่า address binding ทำได้ 3 จังหวะ:

จังหวะได้ address แบบผล
Compile timeabsolute address (fixed)ต้องลงตำแหน่งเดิมทุกครั้ง ย้ายไม่ได้
Load timerelocatable address (not fixed)OS เลือกที่ว่างตอนโหลด แต่โหลดแล้วย้ายไม่ได้
Execution time (run time)เปลี่ยนได้ขณะรันย้ายโปรเซสไปเซกเมนต์อื่นได้ ต้องมีฮาร์ดแวร์ช่วย เช่น base register

2.2 Logical address vs physical address ★

🎯 ต้องทำได้บอกความต่างได้ และคำนวณ physical address จาก base / limit register ได้
🗣 อาจารย์พูดสิ่งที่ควรรู้คือสองคำนี้ต้องรู้ logical address กับ physical address ต่างกันอย่างไร อันหนึ่งเป็นเลขที่ CPU อ้างถึง … สมมติ 346 เขาต้องมี relocation register คือ transform ไปเป็นตำแหน่งจริงใน memory
💡 เข้าใจง่ายๆ: เลขห้องในหอพัก โปรแกรมคิดว่าตัวเองอยู่ "ห้อง 346" (นับจากห้องแรกของตัวเอง = logical) แต่จริงๆ ห้องแรกของมันอยู่ที่ตึกเลข 14000 ห้องจริงจึงเป็น 14000 + 346 = 14346 (= physical)
ส่วน limit คือ "เช่าไว้กี่ห้อง" ถ้าขอห้องเกินจำนวนที่เช่า → โดนไล่ (trap)
  • Logical address = เลขที่ CPU/โปรแกรมอ้าง (มองจากมุมโปรเซส เริ่มที่ 0)
  • Physical address = ตำแหน่งจริงในหน่วยความจำ = base (relocation register) + logical
  • Protection (รูป 3.1.H): ตรวจก่อนว่า logical < limit ถ้าใช่จึงบวก base ถ้าไม่ใช่จะเกิด trap: addressing error
📝 เขียนตอบแบบนี้
Logical address คือ address ที่ CPU/โปรแกรมสร้างขึ้น (มองจากมุมโปรเซส)
Physical address คือตำแหน่งจริงในหน่วยความจำ
MMU แปลงโดย physical = relocation(base) register + logical
เช่น base = 14000, logical = 346 → physical = 14346
และต้องตรวจ logical < limit ก่อน ไม่งั้นเกิด trap (addressing error)

2.3 Dynamic loading / dynamic linking / static linking

🗣 อาจารย์พูด"Dynamic linking and static linking"
  • Dynamic loading (ชีท 3.1.2): โหลดเข้าหน่วยความจำเป็นส่วนๆ เช่น โหลด main program ก่อน แล้วค่อยโหลด subroutine ตอนที่ถูกเรียก จึงประหยัดหน่วยความจำ
  • Dynamic linking (ชีท 3.1.3 เขียนว่า): ถ้าโปรแกรมเรียก subroutine ระบบจะนำ subroutine มาลิงก์เข้ากับตัวโปรแกรม ทำให้โปรแกรมใหญ่ขึ้น
⚠️ ระวัง: นิยามในชีทกับในตำราไม่ตรงกัน ตำรา (Silberschatz):
• Static linking = รวม library เข้าไปในไฟล์โปรแกรมเลยตอน link → ไฟล์ใหญ่ และทุกโปรแกรมมีสำเนาของตัวเอง
• Dynamic linking = เลื่อนการลิงก์ไปทำตอนรัน (ใช้ stub ชี้ไปที่ shared library) → ไฟล์เล็ก และหลายโปรแกรมใช้ library ชุดเดียวกันได้
ข้อความในชีท 3.1.3 ตรงกับ static linking ตอนสอบให้อธิบายเทียบทั้งสองแบบ จะปลอดภัยที่สุด

2.4 Overlay และ Swapping ★

Overlay (รูป 3.1.B two-pass assembler)

สมัยก่อนถ้าโปรแกรมใหญ่กว่าหน่วยความจำ ต้องแบ่งเป็นส่วนแล้วผลัดกันใช้พื้นที่ ส่วนที่ใช้ตลอดคือ symbol table 30K + common routine 20K + overlay driver 10K ส่วน Pass1 (70K) กับ Pass2 (80K) ผลัดกันใช้ที่เดียวกัน

ไม่ใช้ overlay = 70 + 80 + 30 + 20       = 200K
ใช้ overlay    = 30 + 20 + 10 + max(70,80) = 140K

Swapping ★

🗣 อาจารย์พูดสมมติว่ามันมีขนาด block memory ตรงนี้เหลืออยู่ 80 kilobytes … process สองอันยัดเข้าไปพร้อมกันไม่ได้ ก็ต้องมีการสลับเข้าสลับออก … save process control block, load process control block ก็จะถามนิดหน่อย
  • Swap out: เอาโปรเซสที่กำลังทำงานออกจากหน่วยความจำชั่วคราวไปเก็บที่ backing store (ดิสก์)
  • Swap in: นำอีกโปรเซสเข้ามาให้ CPU ทำแทน (เช่น RR CPU scheduling เมื่อหมด quantum)
  • ตอนสลับโปรเซสต้อง save PCB (สถานะ, register, program counter ฯลฯ) ของตัวเดิม แล้ว load PCB ของตัวใหม่ ซึ่งก็คือ context switch

2.5 Single partition: low memory / high memory ★

🗣 อาจารย์พูดคำว่า low และ high address บางทีมันจะเขียน low อยู่ข้างเลข … เราต้องดูเลขนะ บางทีเลขส่วนอยู่ข้างล่าง … low memory OS จะอยู่ที่เลข 0 … หรือบางทีเขาออกแบบมาเป็นแบบให้พื้นที่ว่างตรงกลางก็ได้ ก็จะเกี่ยวข้องกับเรื่อง stack กับ heap
  • Low memory: OS อยู่ที่ address 0 แล้ว user ต่อจาก OS ทันที ส่วนที่ว่างอยู่ท้าย
  • High memory: OS อยู่ที่ 0 แต่ user ไปอยู่ ท้าย (address สูง ใกล้ 512K) ที่ว่างอยู่ตรงกลาง
  • บางระบบเว้นที่ว่างไว้ตรงกลาง เพื่อให้ stack โตลงและ heap โตขึ้นเข้าหากัน
⚠️ อาจารย์เตือนอย่าดูจากตำแหน่งบน/ล่างของรูป ให้ดูเลข address เพราะบางรูปเขียน 0 ไว้ด้านล่าง

2.7 Placement strategy: first / best / worst fit ★

🗣 อาจารย์พูดfirst fit … มีข้อดีข้อเสียยังไง ไปทบทวนครับ สามอย่างเนี่ย
  • First-fit: วางใน hole แรกที่ใส่ได้ (ค้นจากต้นทุกครั้ง หรือค้นต่อจากที่วางล่าสุดก็ได้)
  • Best-fit: วางใน hole ที่เล็กที่สุดที่ใส่ได้ → ต้องค้นทุก hole ยกเว้นมี list เรียงจากเล็กไปใหญ่
  • Worst-fit: วางใน hole ที่ใหญ่ที่สุด → ต้องค้นทุก hole ยกเว้นมี list เรียงจากใหญ่ไปเล็ก
วิธีข้อดีข้อเสีย
First-fitเร็วที่สุด หยุดค้นเมื่อเจอ hole แรกที่พอเศษเล็กๆ กองอยู่ช่วงต้นหน่วยความจำ
Best-fitเหลือเศษน้อยสุด เก็บ hole ใหญ่ไว้ให้โปรเซสใหญ่ต้องค้นทุก hole และได้เศษเล็กมากที่ใช้ต่อไม่ได้
Worst-fitเศษที่เหลือใหญ่ ยังพอใช้ต่อได้ต้องค้นทุก hole, hole ใหญ่หมดเร็ว โปรเซสใหญ่ที่มาทีหลังอาจไม่มีที่ลง
Q1hole = 100, 500, 200, 300, 600 และโปรเซส 212, 417, 112, 426 วิธีใดวางได้ครบทุกโปรเซส
Best-fit: 212→300, 417→500, 112→200, 426→600 ครบทุกตัว ส่วน first-fit กับ worst-fit ทำให้ 426K ต้องรอ (ลองกดในเครื่องมือด้านบนดูได้)

2.8 Fragmentation และ compaction ★

🗣 อาจารย์พูดการแก้ปัญหาว่าบับโบล (bubble) หรือ fragment ใน memory จะแก้ยังไง วิธีแรกคือการเลื่อนให้มันมีพื้นที่ใหญ่กองรวมกัน ซึ่งมันก็จะกินเวลา … big O ของ N คูณกับ K เวลาที่ใช้ในการ copy … มันก็เลยต้องมีการแบ่งเป็น page
  • โปรเซสเข้าออกหลายครั้งจะเกิด hole กระจัดกระจาย ที่ว่างรวมกันพอ แต่ไม่ติดกันจึงใช้ไม่ได้ = external fragmentation
  • Compaction = ย้ายโปรเซสให้ชิดกัน เพื่อรวมที่ว่างเป็นก้อนเดียว เช่น รูป 3.1.I ได้ 100 + 300 + 260 = 660K
  • รูป 3.1.J: วิธีที่ย้ายน้อยที่สุดคือ ย้าย 200K (ย้ายแค่ P3 ไปต่อท้าย P4) ส่วนแบบอื่นย้าย 600K หรือ 400K
  • ข้อเสีย: ช้า เพราะต้อง copy ข้อมูลทั้งหมดที่ย้าย ทางแก้ที่ดีกว่าคือ paging
Contiguous allocation
✅ ง่าย แปลง address แค่บวก base
❌ เกิด external fragmentation รันได้ไม่กี่โปรเซส และต้อง swap หรือ compaction
Paging
✅ ลงเฟรมไหนก็ได้ ไม่ต้องติดกัน จึงไม่มี external fragmentation
❌ มี internal fragmentation (เพจสุดท้ายใช้ไม่เต็ม) และต้องมี page table

2.9 Paging ★

🎯 ต้องทำได้แปลง logical → physical ได้ทั้งเลขฐาน 10 และระดับบิต และบอกได้ว่า page / frame / offset คืออะไร
🗣 อาจารย์พูดaddress ใน logical ถ้าเป็นเรื่อง page จะใช้คำว่า page … frame คือ physical frame ที่ขนาดเท่ากับ page … frame มันจะบอกตำแหน่งเริ่มต้น แล้วก็ CPU อยากอ่านตำแหน่งไหน สมมติว่า page ละ 1K … 0 ถึง 1023
💡 เข้าใจง่ายๆ: หนังสือ 1 เล่มแยกเป็นแผ่น logical memory ของโปรแกรมถูกตัดเป็นแผ่นเท่าๆ กัน (page) แล้วนำไปวางในช่องว่างของ RAM ที่ขนาดเท่ากัน (frame) จะวางช่องไหนก็ได้ ไม่ต้องติดกัน
Page table คือสมุดจดว่า "แผ่นที่ p อยู่ช่องที่ f" ส่วน offset d คือ "บรรทัดที่เท่าไรในแผ่นนั้น" ซึ่งเท่าเดิมทั้งใน page และ frame
logical address  = (p, d)      p = page number, d = page offset
physical address = (f, d)      f = page_table[p], d เท่าเดิม

p = logical div page_size
d = logical mod page_size
physical = f × page_size + d

ตัวอย่างในชีท (รูป 3.1.M) ทำทีละขั้น

memory 32 byte, page = 4 byte, page table = [0→5, 1→6, 2→1, 3→2]

logical 0  (A): p = 0, d = 0 → f = 5 → 5×4 + 0 = 20
logical 5  (F): p = 1, d = 1 → f = 6 → 6×4 + 1 = 25   ← ชีทคำนวณข้อนี้
logical 13 (N): p = 3, d = 1 → f = 2 → 2×4 + 1 = 9

ระดับบิต (รูป 3.1.N)

address 16 บิต, page = 1 KB = 210 → d = 10 บิต, p = 6 บิต (มี 64 เพจ / 64 เฟรม)

logical 1502 = 000001 0111011110  → p = 1, d = 478
page_table[1] = 000110 = 6
physical     = 000110 0111011110  = 6×1024 + 478 = 6622
⚠️ จุดที่มักพลาด• เอา p ไปคูณ page size แทน f (ต้องใช้ f ที่ได้จาก page table)
• ลืมว่า d ไม่เปลี่ยน
• นับเพจเริ่มที่ 1 (ต้องเริ่มที่ 0)
Q2page table เดียวกับรูป 3.1.M (0→5, 1→6, 2→1, 3→2) logical address 10 ได้ physical address เท่าไร
p = 10 div 4 = 2, d = 10 mod 4 = 2 → f = 1 → 1×4 + 2 = 6 (ตัวอักษร K อยู่ที่ตำแหน่งจริง 6 ตรงกับรูป)
Q316 บิต, page 1 KB, page table ช่องที่ 2 = 011001₂ แล้ว logical address 3000 = physical เท่าไร
3000 = 2×1024 + 952 → p = 2, d = 952 → f = 011001₂ = 25 → 25×1024 + 952 = 26552
Q4ทำไม paging ถึงแก้ปัญหา external fragmentation ได้
เพราะแบ่งทั้ง logical memory และ physical memory เป็นชิ้นขนาดเท่ากัน (page = frame) เพจลงเฟรมว่างไหนก็ได้ ไม่ต้องติดกัน ขอแค่มีเฟรมว่างพอ จึงไม่ต้องหา hole ใหญ่ติดกันและไม่ต้อง compaction แต่จะยังมี internal fragmentation ในเพจสุดท้าย

    เช่น ตารางในสไลด์ segment 2 (limit 400, base 4300): (2, 53) → 4353
