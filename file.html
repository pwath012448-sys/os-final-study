5.2 Access methods

  • Sequential access (แบบเทป) อ่าน/เขียนตามลำดับ ใช้ rewind ย้อนกลับ
  • Direct access (แบบดิสก์) กระโดดไปบล็อกที่ต้องการได้เลย ทำ sequential บน direct ได้ดังนี้ reset → cp := 0, read next → read cp; cp := cp + 1, write next → write cp; cp := cp + 1
  • ISAM: master index (binary search) → secondary index (binary search) → actual file block (อ่านแบบ sequential)

5.5 สิทธิ์ไฟล์: 3 สิทธิ์ × 3 กลุ่ม (3 bit) ★

🗣 อาจารย์พูดสิทธิ์ของ file ไปทบทวนครับ สิทธิ์ของ file 3 level … owner แล้วก็ group แล้วก็ other บุคคลทั่วไปครับ แต่ละ user ก็จะมีสิทธิ์ 3 อย่าง ซึ่งเราสามารถ set ผ่าน bit ได้เป็น 3 bit ไปดูเอาเองนะครับอยู่ในหนังสือ
  • ชนิดสิทธิ์ (ชีท): Read, Write (รวม rewrite), Execute, Append, Delete และอื่นๆ เช่น Rename, Copy, Edit
  • วิธีควบคุม: Naming, Password, Access list (ระบุรายคน ถ้าจะให้ทุกคนอ่านได้ต้องใส่ชื่อทุกคน ซึ่งยุ่งยาก) และ Access group แก้ปัญหานี้ด้วยการแบ่งกลุ่มเป็น owner / group / universe
💡 เข้าใจง่ายๆ: แชร์ไฟล์ใน Google Drive (อาจารย์ยกตัวอย่างนี้เอง)เจ้าของ (owner) ทำได้ทุกอย่าง, คนที่เราแชร์ให้ (group) อาจแก้ได้หรือดูได้อย่างเดียว, คนทั่วไปที่มีลิงก์ (others) อาจดูได้หรือเข้าไม่ได้เลย Unix/Linux ทำแบบเดียวกันด้วย 3 บิตต่อกลุ่ม
r = 4 (อ่าน)   w = 2 (เขียน)   x = 1 (execute)
แต่ละกลุ่มรวมเลขกัน → ได้เลข 3 หลัก: owner | group | others

rwx r-x r--  = (4+2+1)(4+0+1)(4+0+0) = 754
rw- r-- ---  = 640   (owner อ่าน/เขียน, group อ่าน, others ไม่ได้อะไร)
chmod 750 file  → rwx r-x ---

5.6 นิยามของระบบที่ secure (state machine) ★

🗣 อาจารย์พูด (วาดใน Paint)นิยามของระบบที่ secure คืออะไร ก็คือ transition ของ state มันไม่ไปยัง non-secure … automata … สถานะ S0 S1 S2 เกิดเหตุการณ์ string a b ก็ transition วนอยู่ในนี้ ถ้ามันวนอยู่ใน secure state ก็ถือว่าระบบมันผ่าน cyber security … OS หรือตัวจัดการส่วนอื่นมันผิดพลาด มันก็จะเกิด transition ที่เราไม่พึงประสงค์ เช่นส่งโทรจันมาทำให้เกิดการ backdoor ออกไปยัง non-secure … พอรู้ปุ๊บก็ปิด transition … คือนิยามด้วย finite state machine
💡 เข้าใจง่ายๆ: ห้องในบ้านที่ปิดประตูหมด state = ห้อง, transition = ประตูที่เปิดเมื่อเกิดเหตุการณ์ (input a, b) ระบบจะ secure ก็ต่อเมื่อประตูทุกบานจากห้องที่ปลอดภัยพาไปได้แค่ห้องที่ปลอดภัย
ถ้ามีประตูลับ (ช่องโหว่ / backdoor / trojan) ที่พาออกไปนอกบ้านได้ ระบบก็ไม่ secure และวิธีแก้คือปิดประตูนั้น (patch)
📝 เขียนตอบแบบนี้
มองระบบเป็น finite state machine: แบ่ง state เป็น secure set กับ non-secure
ระบบจะ secure เมื่อทุก transition (ทุก input/เหตุการณ์) ที่ออกจาก secure state
พาไปได้แค่ secure state เท่านั้น ระบบจึงวนอยู่ใน secure set เสมอ
ถ้า OS ผิดพลาดหรือมีช่องโหว่ (เช่น trojan ทำ backdoor) จะมี transition ไป non-secure
ต้องปิด transition หรือเหตุการณ์ที่ trigger นั้น (patch)

5.7 Domain of protection และ access matrix

  • Object: hardware (CPU, printer, disk, memory segment, tape drive) และ software (file, program, semaphore)
  • Domain เขียนเป็นคู่ <object-name, rights-set> เช่น D2 = { <O2, {write}>, <O4, {print}> } (O4 ใช้ร่วมกับ D3)
  • Access matrix: แถว = domain, คอลัมน์ = object, ช่อง Access(i, j) = สิทธิ์ที่ Di ทำกับ Oj ได้ และ global table เขียนเป็น <domain, object, rights-set> (ถ้าการกระทำ M ∈ Rk จึงอนุญาต)
  • Static = กำหนดตายตัว ส่วน dynamic = มีคอลัมน์ D1–D4 ที่เขียนว่า "switch" ให้สลับไปโดเมนอื่นได้ แล้วได้สิทธิ์เท่ากับโดเมนนั้น เช่น D2 switch ไป D3 จะได้ read F2, execute F3
⚠️ สังเกตตารางในรูป 4.2.B กับ 4.2.C ในชีทไม่เหมือนกันทุกช่อง (เช่น ใน 4.2.B D2 อ่าน F3 ได้ แต่ใน 4.2.C ไม่ได้) ตอบตามตารางที่โจทย์ให้มาเสมอ
