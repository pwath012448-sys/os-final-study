บทที่ 4 · Secondary Storage บางส่วน

ชีท secondary_storage_mng3_3 หน้า 95–104 (10 หน้า) — อาจารย์เปิดในคลิปแค่ช่วงสั้นๆ นาที 23:05–23:50

🗣 อาจารย์พูดSecondary storage เรื่อง hard disk เรื่องการหมุนแม่เหล็ก จะไม่ออกสอบนะครับ
ระหว่างนั้นอาจารย์เปิดหน้า free-space management (bit vector) ผ่านๆ ส่วน allocation methods กับ disk scheduling ไม่ได้พูดถึงในคลิป
🎯 เป้าหมาย (เผื่อออก)เขียน bit vector ตามรูปแบบชีทได้ รู้วิธีจัดการพื้นที่ว่าง 4 แบบกับ allocation 3 แบบ และคำนวณ disk scheduling เป็น

4.1 ทำไมต้องมีหน่วยความจำสำรอง

  • หน่วยความจำหลักมีข้อจำกัด 2 ข้อ: (1) พื้นที่น้อย เก็บถาวรไม่ได้ (2) เป็น volatile ไฟดับแล้วข้อมูลหาย
  • หน่วยความจำสำรอง เช่น magnetic tape, disk โครงสร้างดิสก์: track, cylinder, sector, head — ไม่ออก

4.2 Free-space management

วิธีหลักการ
1. Bit vector (bit map)1 บิตต่อ 1 บล็อก — ชีทกำหนด ว่าง = 0, ถูกใช้ = 1
2. Linked listบล็อกว่างแรกเป็น free-space list head แต่ละบล็อกชี้ไปบล็อกว่างถัดไป บล็อกสุดท้ายชี้ null
3. Groupingบล็อกว่างแรกเก็บ address ของบล็อกว่าง N บล็อก และบล็อกสุดท้ายในกลุ่มเก็บ address ของ N บล็อกถัดไป
4. Countingนับเป็นกลุ่มบล็อกว่างที่ติดกัน (บล็อกเริ่ม + จำนวนบล็อก)
⚠️ ระวังตำราฝรั่ง (Silberschatz) ใช้ ว่าง = 1 แต่ชีทอาจารย์ใช้ ว่าง = 0 ให้ตอบตามชีท ตัวอย่างในชีท: 12 บล็อก ว่าง 2, 3, 4, 6, 8, 9, 10 → 110001010001

4.3 Allocation methods

แบบdirectory เก็บตัวอย่างในชีทข้อดี / ข้อเสีย
Contiguousstart + lengthdata1: start 0, length 3 → บล็อก 0, 1, 2อ่านเร็ว เข้าตรงได้ / เกิด external fragmentation และต้องเลือก hole (first/best/worst fit)
Linkedstart + endData2: 11 → 14 → 16 → 5 → 4 (−1 = จบ)ไม่มี external fragmentation / เข้าตรงไม่ได้ ต้องไล่ทีละบล็อก และเสียที่เก็บ pointer
Indexedindex blockData3: index block 15 = [17, 13, 2, 10]เข้าตรงได้ / เสียบล็อกทำ index
FATstart block200 → 515 → 300 → end-of-fileแบบ linked แต่เก็บ pointer ไว้ในตาราง
